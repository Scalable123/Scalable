# T006 — AI reference analysis and Wikimedia visual search

## Outcome

The Studio now sends a user-selected JPG/PNG/WebP reference to the server-side AI only when the user submits Explore. The AI returns up to three bounded visual-search phrases. The browser queries Wikimedia sequentially with those phrases and replaces available unpinned local image examples with up to three validated Commons references. The existing palette is intentionally left unchanged, and no generated image file is produced.

## Decisions and boundaries

- The upload remains browser-preview-only until explicit submission; it is not saved in localStorage or the board DTO.
- The browser enforces the existing 10 MB image limit. The Node endpoint validates the data URL MIME type, base64 shape, and encoded request size before calling OpenAI.
- The image is sent as an OpenAI Responses API `input_image` alongside the prompt. Image text/instructions are treated as untrusted data by the system instruction.
- Wikimedia similarity is implemented as bounded AI-derived textual search, not pixel-nearest-neighbor matching; Commons Action API does not provide a general visual-similarity search route in this integration.
- At most three Wikimedia search requests/results are used per prompt, sequentially, with duplicate IDs removed. Each result keeps Commons source, creator, and license metadata.
- Only unpinned local sample image slots are replaced. Pinned, imported, and prior Wikimedia references remain preserved during refinement. Palette items are not changed.
- AI-generated imagery is explicitly out of scope for this task.

## Verification

- `node tests/ai-reference.node.cjs` validates invalid image types, malformed data, oversized encoded input, and provider-boundary behavior without calling OpenAI.
- `node tests/wikimedia-source.node.mjs` covers Wikimedia DTO validation.
- `node --check` covers changed JavaScript modules. Browser suites should be run with Playwright when installed; their provider routes must be updated to mock up to three Wikimedia requests and the AI response's `imageQueries` field.
