# T008 — Render AI service configuration

## Outcome

Prepared the Node OpenAI creative-direction service for Render deployment. The service can receive the uploaded reference image from a GitHub Pages frontend, pass it to OpenAI vision, and return bounded text search phrases for the existing Wikimedia flow.

## Decisions

- `OPENAI_API_KEY` remains a server-only Render environment variable and is never placed in frontend configuration.
- `FRONTEND_ORIGIN` is an exact-origin CORS allowlist; project paths are not included in the origin.
- `window.SCALABLE_AI_ORIGIN` is optional so the same Node service can serve both the Studio and AI endpoint, while Pages can target a separately deployed Render service.
- `render.yaml` uses the free Node web service, `npm install`, and `npm start`; Render supplies `PORT`.
- This change does not implement reverse-image search. The uploaded image is analyzed by OpenAI, which returns text phrases used by Wikimedia's text search.

## Verification

- AI reference validation now covers invalid uploads, missing-key fallback behavior, allowed-origin preflight, and rejected origins.
- JavaScript syntax checks cover `ai-service.js` and the new AI-origin module.
- Render configuration and server environment handling were reviewed without exposing a key.
