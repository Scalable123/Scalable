# T004 — Wikimedia Commons image source

## Outcome

Added a server-side Wikimedia Commons image search source. Each explicit prompt submission makes at most one Commons search request and accepts at most one image from that source. The result retains the Commons file page, creator, and license metadata; the application hotlinks the provider thumbnail and does not proxy or persist image bytes.

## Decisions and evidence

- Wikimedia Commons read-only Action API access does not require an API key. No Wikimedia secret is added to configuration or browser code.
- The server sends a descriptive configurable `Wikimedia:UserAgent`, defaulting to the project repository URL. This is required by Wikimedia API policy.
- Wikimedia's current rate-limit guidance lists 200 requests/minute for an identified client using a compliant User-Agent. The shared source budget is capped at 180 requests/minute for headroom; HTTP 429 responses block the source for one minute.
- Requests are serialized with the existing Unsplash request, and provider redirects are disabled. Search requests use `gsrlimit=1`, namespace 6 (files), and `iiurlwidth=1200`.
- Results without a usable Commons source URL, creator metadata, or license metadata are rejected. Attribution is rendered as text and links back to the Commons file page.
- The existing `docs/BACKEND.md` and historical task records were preserved; the Wikimedia handoff was appended to `BACKEND.md`.
