## Decisions

- Search only on an explicit, nonblank prompt submission. Initial load, New mood board, saved-board opening, filters, and import previews do not search Wikimedia.
- Permit at most one new Wikimedia image per submitted prompt. Fetch metadata for up to three ranked candidates in one API request and select at most one. Never paginate, retry automatically, or load unselected image files. Older pinned images remain user choices and do not count as newly pulled images.
- Apply a conservative shared-origin throttle (one request per 6.1 seconds), single in-flight request, persistent provider cooldown, finite timeout, and bounded in-memory query cache. Respect `Retry-After` for HTTP 429/503 and API throttling/lag errors. Browser controls cannot guarantee the provider's aggregate IP quota; provider responses always override local availability. No quota circumvention.
- Require supported raster media, trusted HTTPS media/source/license URLs, a recognized CC BY/CC BY-SA/CC0/public-domain-mark license, and readable author/license metadata. Skip bad-file flags, restrictive/ambiguous metadata, and missing credits. Render metadata as text, retain credit/attribution/license/source, and link the original file page. These checks do not establish every non-copyright permission for every use.
- Leave samples available on empty, rejected, failed, throttled, cancelled, or timed-out lookups. Explain the provider outcome in a persistent status region. Uploaded references stay local.
- Keep existing imported media and pinned Wikimedia results through refinement; deduplicate by stable provider identity. Abort stale lookups when replacing the board and retain the existing board-version guard.
- Reuse the existing variable-image layout rules for boards with Wikimedia images; show readable attribution outside the cropped preview rather than hiding it behind hover.
