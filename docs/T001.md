# T001 — Documentation audit and GraphQL backend direction

Date: 2026-11-14. Branch: `docs/graphql-backend-audit-t001`.

## Request and discovery

Audit all project documentation against the current implementation, specify GraphQL instead of Supabase for the application backend, document decisions, validate affected behavior, and push a new branch for human merging.

The repository is `/workspace/Scalable`. Guidance was discovered in `docs/` and `documentation/`; both frontend guides and every integration/deployment/asset Markdown guide were read. No `AGENTS.md` or backend Markdown guide existed. The next-best approach was to inspect the frontend service/auth modules, tests, package manifest, and deployment workflow, then create [BACKEND.md](BACKEND.md) as the shared backend handoff.

## Decisions and outcomes

1. Keep this task scoped to documentation. No feature, dependency, identity configuration, or deployment changes are needed for the requested audit.
2. Record GraphQL as the selected application API/data-access direction instead of Supabase. Explain that GraphQL is not a database engine. Keep the database/ORM/server library/replacement identity service undecided rather than inventing an implementation.
3. Distinguish the selected architecture from source reality: boards use localStorage; there is no backend/GraphQL server; existing Supabase Auth remains legacy code requiring an explicit migration. Preserve accurate auth/config/test references rather than relabeling those calls as GraphQL.
4. Replace obsolete proposed REST contract tables with consistent proposed GraphQL operations. Describe the inactive REST adapter as legacy implementation code and explain the transport/lifecycle changes it needs. Keep protocol-specific callbacks/uploads separate where appropriate.
5. Reconcile stale login/account/deployment claims with actual sign-in, recovery, session, password-update, and sign-out calls. Preserve the signup/recovery preview distinctions and document existing limitations.
6. Preserve the pre-existing README link addition and expanded untracked `documentation/FRONTEND.md`, incorporate the expanded guide in the documentation branch, and reconcile it with the focused handoffs. Baseline copies were saved outside the repository under `/workspace/work/task-001/`.
7. Keep asset provenance guidance unchanged after checking it against committed sample assets; no asset behavior or rights changed.
8. Create a new branch from the existing `front-end-design` checkout. Push only the documentation commit to that new branch; leave merge and deployment to humans.
